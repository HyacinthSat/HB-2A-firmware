# 气球软件工作需求

本文件是根据 `需求.md` 和已经确认的回答整理的正式程序需求。

现有测试工程的硬件连接继续使用，摄像头时钟使用 PC7/TIM3 输出 8 MHz，Flash 使用 IS25LP128F。
旧版 `ns.md` 中的 SSTV、每小时固定拍摄时间等内容不再使用。

高速模式的主要目的，是验证可变速率测控传输格式，并把图片文件下传到地面。气球上的数据源有限，高速模式只保留 SSDV 下行，不实现通用文件、遥测或其他数据源的高速下行。

卫星格式文档中的传输帧、RS、PN17、CSM、卷积码和动态参数协商按原文档使用，气球只替换数据源和任务流程。

## -1. 遥控上行

遥控上行使用 SX1278，频率为 435.400 MHz。

调制制式为 GMSK，BT=0.5，H=0.5，速率为 4800 bps。

遥控数据结构如下：

- 16*0x55 极性前导
- 0x1ACFFC1D 同步码
- BCH 码块
- CRC-16

前导和同步码不进行 NRZI。BCH 数据部分按 MSB 发送，使用 NRZI，不交织。

BCH 使用 CCSDS TC 的 BCH 编码，每个 BCH 码块可以放 7 Byte 数据。不足 7 Byte 的位置使用 0x20 填充。

CRC 使用与 APRS 相同的 CRC-16/CCITT 算法，CRC 计算范围为原始数据，不包括 BCH 编码后的校验数据。

码块数量根据命令内容动态变化。无法解析、CRC 错误或 BCH 校验失败的数据包直接丢弃。

Free Text 固定使用 1 个 BCH 码块，最多 7 Byte。超长内容截断，空参数保留并继续处理。

SX1278 的 DIO 接收、帧同步和超时处理由程序完成。

有效指令需要发送应答。参数错误、图片不存在、设备忙或执行失败时，发送错误提示包。

### -1.1 遥控指令字段

每条指令的第一个 BCH 数据块是指令名，后面的 BCH 数据块按表中顺序放参数。每个参数使用 ASCII 字符，不在参数之间放逗号。每个 BCH 数据块最多 7 Byte，不足部分补 `0x20`，超长参数截断。

| 指令 | 参数顺序 | 说明 |
| --- | --- | --- |
| `EXPR` | 无 | 进入试验工作模式。 |
| `TRANPD` | `from`、`to`、`path`、`free_text` | 仅标准工作模式接受。`path` 必须为 `HB-2A`；空参数照样保留并转发。 |
| `CAPTR` | `camera`、`width`、`height`、`quality` | `camera` 为 `A` 或 `B`；A 对地，B 对天；尺寸必须为 `128`、`96`；`quality` 为 SSDV 质量 0～7。 |
| `REQF` | `n` | 请求编号为 `当前图片编号-n` 的图片，`n=0` 为最新拍摄成功的图片。 |
| `HSPAR` | `RateID`、`CodeID`、`IntlvID` | 选择高速图片传输参数。三个参数均为十进制数字。 |
| `CFRM` | 无 | 确认使用当前已经协商的参数，开始发送图片。 |
| `CANCEL` | 无 | 取消当前高速协商或传输。 |
| `CHPRAM` | `RateID`、`CodeID`、`IntlvID` | 在收到 `CFRM` 前修改参数，修改后重新检查。 |

`CAPTR` 和 `REQF` 本身只负责选择图片或拍摄图片，不携带高速参数。收到这两条指令后，气球先回 `ACK` 和支持参数，再等待 `HSPAR`。

常规 GMSK 下行的应答和错误提示也使用 ASCII 文本，例如：

```text
ACK,CAPTR
ACK,HSPAR,0,1,1
ERR,CAPTR,BUSY
ERR,REQF,NOFILE
ERR,HSPAR,PARAM
```

这些文本按常规 GMSK 下行帧发送，超过 219 Byte 时截断。

## 0. 上电程序

上电后依次初始化设备，每个设备之间间隔 0.5 s。

每个设备最多初始化和自检 3 次。8 个设备全部初始化和自检结束后，统一拼装并发送一份完整的自检反馈包。

自检报告必须包含以下 8 个设备：

- 01：INA3221
- 02：SX1278
- 03：SI5351
- 04：FLASH
- 05：BME280
- 06：MAX-M10S
- 07：CAM_A
- 08：CAM_B

8 个设备放在同一个 APRS 自检报告包中。状态码固定为 4 个 ASCII 字符，正常状态使用 `0000`。一个设备可以带多个状态码，状态码之间用逗号分隔；不同设备之间用分号分隔。同一种错误在不同设备中使用同一种错误代码。

格式如下：

```text
BG7ZDQ-11>APZDQ7:rst_times,01,0000;02,SPIE,TXER;03,0000;04,WRIT,READ;05,0000;06,UBXE;07,0000;08,0000
```

第一个字段为累计复位次数，之后每段依次为设备编号和一个或多个四字符状态码。设备编号固定为 `01`～`08`，每次反馈都包含全部 8 个设备。

当前统一使用的状态码如下：

| 状态码 | 含义 |
| --- | --- |
| `I2CE` | I2C 无应答或事务失败 |
| `SPIE` | SPI 事务失败 |
| `IDER` | 器件 ID 不匹配 |
| `READ` | 读取或回读校验失败 |
| `WRIT` | 写入或寄存器配置失败 |
| `ERAS` | Flash 擦除失败 |
| `CONF` | 配置流程失败 |
| `TXER` | 射频发射状态异常 |
| `TIME` | 等待或操作超时 |
| `RANG` | 读取数值超出有效范围 |
| `UART` | 串口收发失败 |
| `UBXE` | UBX 数据无效或格式错误 |
| `DMAE` | DCMI/DMA 传输失败 |
| `JPEG` | 未找到有效 JPEG 图像 |
| `CLCK` | 摄像头时钟或 PLL 配置失败 |
| `BUSY` | 设备或传输资源正忙 |

驱动新增错误时，按错误本质复用上述代码；确实无法归类时再增加新的四字符代码。

按当前驱动，自检时各设备允许上报的代码范围如下：

| 设备 | 代码范围 |
| --- | --- |
| `01` INA3221 | `I2CE`、`IDER`、`READ`、`RANG` |
| `02` SX1278 | `SPIE`、`READ`、`WRIT`、`TXER`、`TIME` |
| `03` SI5351 | `I2CE`、`WRIT`、`CONF`、`TIME` |
| `04` FLASH | `SPIE`、`WRIT`、`READ`、`ERAS`、`TIME` |
| `05` BME280 | `I2CE`、`IDER`、`CONF`、`READ`、`RANG` |
| `06` MAX-M10S | `UART`、`UBXE`、`CONF`、`TIME` |
| `07` CAM_A | `I2CE`、`IDER`、`CONF`、`CLCK`、`DMAE`、`JPEG`、`TIME` |
| `08` CAM_B | `I2CE`、`IDER`、`CONF`、`CLCK`、`DMAE`、`JPEG`、`TIME` |

某次重试成功时，该设备最终状态为 00。此前失败的情况在对应的错误结束反馈中保留。

各设备自检要求如下：

- INA3221：检查 I2C 应答，然后读取数值。
- SX1278：检查 SPI 通信，然后在 144.640 MHz 发射 1 s 载波，功率设置为 20 dBm。软件确认芯片已经正常进入并保持发射即可。
- SI5351：检查 I2C 应答，然后发射 14.0956 MHz 载波。
- FLASH：检查 SPI 通信，在安全空闲区域写入数据，再读取并核对。
- BME280：检查 I2C 应答，然后读取数值。
- MAX-M10S：下发配置指令，再检查串口数据和 UBX 格式。
- CAM_A：检查 SCCB 应答，再设置或读取寄存器。
- CAM_B：检查 SCCB 应答，再设置或读取寄存器。

`rst_times` 为掉电后保存的累计 MCU 启动次数，第一次启动为 0，不记录复位原因。

每次上电产生的 APRS 自检包在各地区常用 APRS 频点发送，每个频点发送 2 次。不管是否已经定位都发送。GNSS 超时包使用相同的频点和次数。

SI5351 初始化失败时，跳过首次 WSPR 后进入标准工作模式。

FLASH 初始化失败时，允许使用 RAM 中的图片进行图传。

CAM_A 或 CAM_B 其中一路失败时，跳过该路，继续使用另一路。

本次上电失败的设备不自动重新初始化。下一次断电后重新上电时再次尝试。

### 0.1 GNSS

GNSS 配置完成后开始等待定位，等待时间为 5 分钟。

定位成功的条件为：三维定位有效，UTC 日期有效，UTC 时间有效，UTC 已完全解析。

5 分钟内没有定位成功时，发送：

```text
BG7ZDQ-11>APZDQ7:GNSS Failed!
```

然后拉低 `GNSS_RST` 复位 GNSS。

GNSS 连续 3 次超时后，复位 GNSS，再复位 MCU。MCU 重启后重新开始上电流程，不保存超时次数。

运行过程中 GNSS 失锁时，使用最后一次有效位置和本地保存的时间继续运行。

WSPR 遥测带有定位和数据有效位。APRS 遥测在 B 字段的压缩十六进制中标记无效状态。

传感器失效时，相关数据使用 00 或默认值，但不影响仍然有效的定位状态。定位无效时使用经纬度 00 对应的网格和默认数据，并标记数据无效。

## 1. 标准工作模式

标准工作模式的时间以 GNSS 获得的 UTC 时间为准。

### 1.1 成像

气球使用两个摄像头轮流拍摄：

- CAM_A：对地
- CAM_B：对天

图像尺寸为横向 128*96。

摄像头输出使用最高 JPEG 质量，SSDV 质量为 3。

拍摄完成后立即开始传输该图片。

一个 SSDV 数据帧拆成 I、J、K 三个 APRS 包，I、J、K 连续发送，包之间间隔 3 s。

每 2 分钟发送一整组 I、J、K。计时从拍摄完成开始。积压的图片仍然每 2 分钟发送一组，不能把积压的多组图片合并后连续发送。每张图片只发送一遍。

当前确认的拍摄流程为：拍摄对地，传完；拍摄对天，传完；再拍摄对地……循环

### 1.2 遥测

WSPR 遥测的发射时隙为每十分钟的 02 分和 04 分：

- 02 分：标准 WSPR
- 04 分：编码遥测 WSPR

APRS 遥测的发射时隙为 01 分和 06 分，每次遥测连续发送 2 次，发送间隔为 3 s。

上电后不额外插入首次 WSPR，按照正常的每十分钟 `:02` 和 `:04` 时隙发送。

继续使用测试工程中的呼号、ID13=03、WSPR 频率基准 14.097140 MHz、APRS 字段和健康位。

WSPR 电压使用 3.3 V 负载侧母线数据，高度及其他数据范围沿用测试工程的编码限制。

WSPR 和 APRS 不同时发射。距离 WSPR 开始不足 2 s 时，不再启动新的 APRS 或图传数据包。

WSPR 发射期间 SX1278 不监听上行，WSPR 发送完成后再恢复接收。

### 1.3 APRS 频率

参考高空气球和 APRS 网络的常用做法，使用 GNSS 位置选择区域频点，不在全球固定使用一个频率：

| 区域 | 频率 |
| --- | ---: |
| 北美 | 144.390 MHz |
| 欧洲 | 144.800 MHz |
| 澳大利亚 | 145.175 MHz |
| 日本 | 144.640 MHz |
| 新西兰 | 144.575 MHz |
| 亚洲及其他区域 | 144.640 MHz |

定位无效、位置不在表格范围内、公海或区域判断不明确时使用 144.640 MHz。区域采用经纬度矩形判断，边界没有命中时走默认频率。

频率只在发射空闲时切换。GNSS 连续 3 次有效定位结果都落入新区域后，才更新当前频率；正在发射的 APRS、WSPR 或图传包不得中途改频。

这个方案参考了 Pi In The Sky 的 APRS 频率说明和 AMSAT-UK 的气球项目：北美使用 144.390 MHz，欧洲使用 144.800 MHz，气球跨区域后切换到当地频点。

- https://www.pi-in-the-sky.com/index.php?id=aprs-config
- https://amsat-uk.org/2015/02/25/aprs-balloon-heads-for-uk/

### 1.4 转发

标准工作模式下，收到 `TRANPD` 数据包后进行转发，其他指令忽略。

转发下行固定使用 144.925 MHz，不使用当地 APRS 网关频率。

Path 必须先检查为 `HB-2A`，然后写入 AX.25 地址，并设置已经转发标志。

源呼号、目的呼号、Path 或 Free Text 为空时照样转发。字段太长时截断。

收到有效包后等待发射空档再发送。重复收到的包照发，不去重。

转发队列满时丢弃最新收到的包。

## 2. 试验工作模式

试验工作模式和测试工作模式为同一个模式。

试验工作模式分为试验常规模式和试验高速模式。

在标准工作模式的其他时间，SX1278 保持在 435.400 MHz、4800 bps、GMSK 接收状态。

收到 `EXPR` 指令后进入试验工作模式。

有效指令刷新 5 分钟计时器。拍摄和高速发送期间暂停计时。

连续 5 分钟没有有效指令时，返回正常工作模式并重启 MCU。

试验工作模式不接受 `TRANPD` 指令。

试验模式中的上行格式仍为：

- 16*0x55 极性前导
- 0x1ACFFC1D 同步码
- BCH 码块
- CRC-16

### 2.0 常规 GMSK 下行

常规 GMSK 下行固定使用 4800 bit/s、GMSK、BT=0.5、H=0.5，对应 `RateID=0`。常规模式不协商参数，固定使用 `IntlvID=1` 和 `CodeID=1`（CCSDS 标准 1/2 卷积码）。

APRS 遥测文本作为常规 GMSK 的业务数据。文本内容直接使用原来 APRS 信息中的 ASCII 文本，包括呼号、目的地址、位置、传感器数据和状态字段；不带 AX.25 FCS、比特填充或 AFSK 字段。

发送前将 ASCII 文本截断或用 `0x20` 补齐到 219 Byte，然后加 4 Byte 传输帧主头，组成 223 Byte 数据区：

- 传输帧版本：`00`
- 航天器编号：`0`
- 虚拟信道编号：`1`
- 不使用副头

发送端固定按以下顺序处理：

```text
219 Byte ASCII 遥测（不足补 0x20）
-> 添加 4 Byte 主头（虚拟信道 1）
-> RS(255,223)
-> PN17 加扰
-> 添加 CSM 0x1ACFFC1D
-> CodeID=1 卷积编码
-> GMSK 4800 bit/s
```

每个 RS 码字独立初始化 PN17。CSM 不参与 PN17 加扰，但参与后续卷积编码。前导使用 `0x55`，同步码使用 `0x1ACFFC1D`。

常规 GMSK 下行承载以下文本：遥测、上电自检、GNSS 超时、命令应答和错误提示。每个业务消息单独形成一个 255 Byte RS 码字，不能把多条消息拼进同一个数据区。

### 2.1 动态高速链路

高速下传不是固定使用一个速率。气球先在 4800 bps GMSK 常规模式下接收指令，再根据双方协商的参数切换到试验高速模式。

收到 `CAPTR` 或 `REQF` 后，开始高速链路协商：

1. 气球发送 ACK，并广播当前支持的高速参数。
2. 气球等待地面发送高速参数，等待时间为 10 s。
3. 没有收到参数时，退出协商并回到常规模式。
4. 收到参数后检查是否合法。不合法时发送拒绝信息，继续等待参数。
5. 参数合法后发送连接建立信息，并等待地面反馈 5 s。
6. 5 s 内没有收到反馈时，重新发送连接建立信息，最多发送 3 次。3 次都没有成功时退出高速模式。
7. 收到 `CANCEL` 时取消本次高速传输并回到常规模式。
8. 收到 `CHPRAM` 时使用新参数重新检查，不重新开始整套上电流程。
9. 收到 `CFRM` 后开始发送地面请求的图片。

图片发送期间暂停试验模式的 5 分钟计时器，不监听上行。图片发送完成后回到试验模式，继续等待下一条有效指令。

高速参数至少包含以下内容：

- `RateID`：速率编号。
- `CodeID`：卷积编码模式。
- `IntlvID`：RS 交织编号。

高速协商控制文本固定使用以下字段顺序，字段之间用逗号分隔：

```text
ACK,<request>
HSSUP,<rate_mask>,<code_mask>,<intlv_mask>
HSCON,<RateID>,<CodeID>,<IntlvID>
HSREJ,<reason>
```

支持掩码按位表示编号是否支持：`rate_mask` 的 bit0～bit5 对应 `RateID=0～5`；`code_mask` 的 bit0～bit3 对应 `CodeID=0～3`；`intlv_mask` 的 bit0～bit5 依次对应 `IntlvID=1、2、3、4、5、8`。当前完整支持时发送 `HSSUP,3F,0F,3F`。

收到合法参数后发送 `HSCON`，收到 `CFRM` 后开始图片传输。参数不合法发送 `HSREJ,PARAM`；设备忙发送 `HSREJ,BUSY`；图片不存在发送 `HSREJ,NOFILE`；收到 `CANCEL` 后发送 `ACK,CANCEL` 并退出。

`RateID` 定义如下：

| RateID | 速率 | 频偏 |
| --- | ---: | ---: |
| 0 | 4800 bit/s | 1200 Hz |
| 1 | 9600 bit/s | 2400 Hz |
| 2 | 19200 bit/s | 4800 Hz |
| 3 | 38400 bit/s | 9600 Hz |
| 4 | 57600 bit/s | 14400 Hz |
| 5 | 115200 bit/s | 28800 Hz |

所有速率使用 GMSK，BT=0.5，H=0.5。频偏按 `速率/4` 设置。

每次高速传输开始前重新选择 `RateID`、`CodeID` 和 `IntlvID`。一次图片传输开始后参数保持不变，当前图片传输完成后，下一次高速传输可以重新协商。

`IntlvID` 支持 1、2、3、4、5、8。`IntlvID=1` 表示不进行多码字交织，其他值表示交织深度。地面选择的参数必须属于气球广播的支持列表。

### 2.2 高速 SSDV 帧和传输帧

高速模式只下传 SSDV 图像数据，不实现通用文件、遥测或 CFDP 高速传输。

SSDV 的图像字段、CRC-32 和数据包编号按《风信子一号测控与数传制式文档》执行。编码器呼号只参与 CRC-32 计算，不进入发射流。下面的偏移是最终传输帧数据区偏移，不包含 RS 校验。SSDV 数据先装入传输帧，再由传输帧统一添加 RS 校验。RS 校验不在 SSDV 数据阶段重复添加。

| 偏移 | 名称 | 长度 | 说明 |
| ---: | --- | ---: | --- |
| 0 | 传输帧主头 | 4 Byte | 见下方定义 |
| 4 | 图像编号 | 1 Byte | 使用拍摄时分配的图片编号的低 8 位 |
| 5 | 数据包编号 | 2 Byte | 每张图片从 0 开始 |
| 7 | 图像宽度 | 12 Bit | MCU 横向块数 |
|  | 图像高度 | 12 Bit | MCU 纵向块数 |
| 10 | 保留、质量、EOI、子采样 | 1 Byte | 质量字段为原质量 XOR 4 |
| 11 | 首 MCU 指针 | 1 Byte | 没有时为 0xFF |
| 12 | MCU 索引 | 2 Byte | 没有时为 0xFFFF |
| 14 | SSDV 有效载荷 | 205 Byte | 原始 SSDV 数据 |
| 219 | CRC-32 | 4 Byte | CRC-32/ISO-HDLC |

该版本的 SSDV 与原版不同，需要自行在原版编码器：
https://github.com/fsphil/ssdv/tree/master

的基础上完成修改。

** SSDV Over APRS的原有编码器不变 **

128*96 图像使用当前 SSDV 的 2×2 子采样时，宽度为 8 个 MCU，高度为 6 个 MCU。子采样字段为 0。

CRC-32 的计算范围为：编码器呼号 `BG7ZDQ`，以及图像编号、数据包编号、图像尺寸、标志、MCU 信息和有效载荷；不包括 CRC-32、传输帧主头和 RS 校验。编码器呼号虽然参与 CRC 计算，但不发送。

SSDV 包生成后，放入原文档定义的精简传输帧。传输帧主头固定为 4 Byte，不使用副头：

- 传输帧版本：`00`
- 航天器编号：`0`
- 虚拟信道编号：`2`
- 副头标志：不使用
- 主信道帧计数和虚拟信道帧计数：按原文档递增

传输帧主头和 SSDV 数据组成 223 Byte 数据区后，再添加 32 Byte RS 校验，形成 255 Byte RS 码字。传输帧主头的位域、字节序和计数规则按原文档执行；不能把同一个 SSDV 数据重复放入两个 RS 层。

主头的位域和字节序按原文档编码。气球固定使用传输帧版本 `00`、航天器编号 `0`、虚拟信道编号 `2`，不使用副头。

RS 使用 CCSDS TM 131.0-B-6 的 RS(255,223) 参数：

- GF(256)。
- 本原多项式：`x^8+x^7+x^2+x+1`，十六进制为 `0x187`。
- `NROOTS=32`，`FCR=112`，`PRIM=11`，`IPRIM=116`。
- 前 223 Byte 为数据，后 32 Byte 为校验。
- 每个码字最多纠正 16 个 Byte 错误。
- 第一版使用常规字节表示，不使用 dual-basis 转换。
- 交织深度由 `IntlvID` 协商决定，RS 码字按交织深度组成一个高速传输组。`IntlvID=1` 时不交织。

发送端的编码顺序如下：

```text
SSDV 数据（不发送编码器呼号）
-> 添加 4 Byte 传输帧主头，形成 223 Byte 数据区
-> 添加 RS(255,223) 码块，并按 IntlvID 交织
-> 对 RS 码字或交织后的 RS 码块进行 PN17 加扰
-> 添加 CSM（CSM 不加扰）
-> 按 CodeID 进行卷积编码
-> GMSK 调制
```

卷积码参数如下：

- 约束长度 K=7。
- 生成多项式使用 CCSDS/NASA 标准的 `G1=171(octal)`、`G2=133(octal)`。
- `CodeID=0`：不使用卷积码。
- `CodeID=1`：1/2 码率，C2 输出反相，穿孔模式 `11`。
- `CodeID=2`：2/3 码率，C2 输出不反相，穿孔模式 `11 01`。
- `CodeID=3`：3/4 码率，C2 输出不反相，穿孔模式 `11 01 10`。
- 穿孔模式循环使用，不能在一帧中途改变。
- 线上输出顺序和寄存器移位方向遵循 CCSDS TM 131.0-B-6；不能直接把普通卷积码实现当作兼容实现。
- 一次图片传输中，卷积模式不能改变；下一次图片传输可以重新协商。

卷积编码按 CCSDS 131.0-B-6 实现。每个独立卷积编码块开始时清零编码器，结束时按标准加入 K-1 个零比特进行格形终止；尾比特也经过当前 CodeID 的卷积编码和穿孔后发送。卷积块的边界、终止方式和穿孔相位按标准处理，不自行跨块保持状态。CodeID=0 时不添加卷积编码和尾比特。

地面端的软判决数值和接口由所用解调、Viterbi 译码库适配，不作为气球协议的待定字段。有标准的细节按标准实现，没有规定的实现细节参考成熟库，并用编码、译码测试向量核对。

PN17 使用原文档定义的 `x^17+x^14+1`，初始化和每个 RS 码字的重新开始方式按原文档执行。CSM 使用 `0x1ACFFC1D`，在 PN17 加扰后添加，CSM 本身不经过 PN17，然后将完整数据送入卷积编码。前导使用原文档定义的 `0x55`。

接收端按相反顺序处理：卷积译码、CSM 检查和去除、PN17 解扰、RS 纠错、传输帧解帧、SSDV CRC-32 检查。RS 或 CRC-32 错误的 SSDV 帧丢弃。

### 2.3 CAPTR

拍摄指令增加摄像头参数：

- A：对地摄像头
- B：对天摄像头

质量参数指 SSDV 质量，摄像头输出 JPEG 使用最高质量。尺寸固定为 128*96。拍摄完成后只生成 SSDV 数据，不生成其他高速下行数据。

### 2.4 REQF

每次拍摄成功后直接给图片编号，从 0 开始递增。CAM_A、CAM_B、标准模式和试验模式共用同一个编号序列；拍摄失败不增加编号。

`REQF,n` 请求的图片编号为 `当前图片编号-n`。当前图片编号就是最新拍摄成功的图片编号。例如当前编号为 20，n=0 请求图片 20，n=1 请求图片 19，n=5 请求图片 15。

收到 REQF 时确定目标编号，本次传输始终使用该图片。编号小于 0、尚未拍摄图片，或目标图片已经被覆盖、无法读取时返回错误，不换成其他图片。

Flash 目录保存完整图片编号，不能用 SSDV 的单字节编号查找图片。SSDV 图像编号使用拍摄编号的低 8 位，超过 255 后按 256 回绕；重传同一张图片沿用该编号，不按发送次数重新编号。

## 3. 图片存储

Flash 中保存 JPG 原图。

Flash 空间不足时覆盖最旧图片。

掉电后不保存图片目录、图片编号和未完成的传输进度。

`REQF` 按 `当前图片编号-n` 读取 JPG，并使用该图片拍摄时的编号生成 SSDV。图片文件只作为 SSDV 的输入，不使用 CFDP 或其他通用文件传输协议。
