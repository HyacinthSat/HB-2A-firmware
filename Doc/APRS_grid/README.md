# APRS 1200 bps参考网格 v2

核查日期2026-10-09；仍为1°×1°，纬向约111 km，经向约111×cos(纬度) km。**频率候选图，不是接收覆盖图。** 未接入气球发送流程。

频率及接收站核查见[FREQUENCY_AUDIT.md](FREQUENCY_AUDIT.md)，逐组依据见[frequency_rules.json](frequency_rules.json)。

## 本次改变

- 保留原有六个频点，新增145.570与144.930，补全有运营依据的部分美洲、非洲及中东地区。
- 已知频率+未确认/未映射区域：优先保留已知频率，与多边形处理顺序无关。
- 多个已知频率：保留全部候选位，不再丢弃为无频率。阿根廷也保留144.390及144.930两候选，见核查报告。
- 去除法国等欧洲国家远方海外多边形自动继承欧洲频点的错误。
- C数组改为逐行RLE，保留随机查询，不需要解压整张图。

## 压缩结果

|方案|数据字节|说明|
|---|---:|---|
|原uint8网格|64,800|原版基准|
|v2原始频率位图uint16|129,600|测试用完整参考|
|v2字典索引4 bit打包+字典|32,432|当前字典16项|
|zlib压缩字典索引+字典|2,829|不含解压代码、工作内存、频率表；不适合直接随机访问|
|选用：逐行RLE+索引+字典|5,748|随机查询，无整图解压|
|选用：再加8项Hz频率表|**5,780**|C数组sizeof实测，约5.64 KiB，比原网格少91.08%|

最后一项不含查询函数机器码及链接器对齐。头文件中的static const若被多个编译单元包含并使用，可能产生多份表；正式集成时建议由一个.c包含并导出查询接口。

每行将连续相同格合并为区间；每区间uint16低9位存结束列（不含，1～360），高7位存字典索引。181项uint16行偏移找到所属行，二分搜索该行区间。当前共2,677个区间，每行最多30个，通常最多5次区间比较。查表无堆分配，RAM仅需少量局部变量。

## 文件格式及查询

- `aprs_1deg.h`：压缩C数组、频率表、查询函数，固件集成优先使用。
- `aprs_1deg_rle.bin`：little-endian，181个uint16行偏移，随后字典uint16，再后区间uint16；数量见JSON。频率表不在此bin内。
- `aprs_1deg.bin`：64,800个字典索引uint8，仅调试用。**v2索引含义已变，不兼容v1固定区域编号**；字典见JSON，不能持久化索引为业务ID。
- `aprs_1deg_masks.bin`：64,800个little-endian uint16候选位图，仅用于测试还原；不应同时放入固件。
- `aprs_1deg.json`：格式、字典、分配依据、压缩统计、源数据SHA256。
- `aprs_1deg.png`：参考图，深色代表多个已知候选，灰色为未确认。
- `station_source_checks.json`：带抓取时间的findU 1,335条网关报告及其他站点访问结果；不作为地图的自动输入。

返回值按位定义：

|位|候选MHz|
|---|---|
|0|144.390|
|1|144.800|
|2|144.640|
|3|144.660|
|4|145.175|
|5|144.575|
|6|145.570|
|7|144.930|

特殊返回：0表示未映射候选，0x8000表示频率未确认，0x4000表示定位无效/坐标越界。前两者**都不表示没有接收站**。已知候选不会带0x8000；多个候选按位或。

```c
uint16_t mask = aprs_grid_lookup_e7(latitude_e7, longitude_e7, position_valid);
uint32_t hz = aprs_grid_single_frequency_hz(mask);
/* hz仅在恰好一个已知候选时非零。不能把0交给射频驱动。 */
/* 多候选时由业务层保留、选择或安排候选频率；本参考不改变发射行为。 */
```

GNSS整数单位1e-7度。行由南向北，列由西向东，负数先平移后整除，不会发生向零截断造成的西/南半球偏移。+180°经度归一化为-180°，+90°纬度归入最后一行；其他越界值拒绝。

## 地图与频率边界局限

Natural Earth 1:50m国家多边形与每格做面相交，不仅采样中心点。格子有任何有面积的已知区域交集，即保留其频率，因此会延伸到同格近海。没有按接收站位置或气球高度做几百公里的海上覆盖扩展。

国别候选代表查询参考：局部网络资料不能证明全国统一，更不能证明整格有覆盖。多频边界与阿根廷的多网络候选均保留，不任意选一个频率。未知地区没有被自动当作亚洲/中国。

地图源：[Natural Earth国界](https://github.com/nvkelso/natural-earth-vector/blob/master/geojson/ne_50m_admin_0_countries.geojson)，[公开领域条款](https://www.naturalearthdata.com/about/terms-of-use/)。保留本地快照`countries_50m.geojson`，可离线重建。1:50m可能遗漏小岛/小地区，格子尺寸不是精确边界误差保证。

## 验证与重建

在仓库根目录：

```powershell
python Doc/APRS_grid/build_grid.py
gcc -std=c11 -O2 -Wall -Wextra -Werror Doc/APRS_grid/test_grid.c -o "$env:TEMP/hb2a_aprs_grid_test.exe"
& "$env:TEMP/hb2a_aprs_grid_test.exe" Doc/APRS_grid/aprs_1deg_masks.bin
```

生成器依赖numpy、shapely、matplotlib，运行本身不联网。验证包括：已知优先合并、13个地理样本、海外领地、全部64,800格RLE还原；C端194,400个格内/边界查询，以及日期变更线、极点、无效定位和频率位图。检查通过不等于全球频率或接收覆盖已逐格实测。

`check_station_sources.py`是独立的联网报告抓取工具，更新列表时调用；收到HTTP 200验证页会标记browser_challenge，不将其当成有效接收记录。

原固件日本频率仍为144640000；本任务修改的是参考网格和查表实现，尚未将144660000及压缩表接入`APRS_SelectFrequencyHz()`。
